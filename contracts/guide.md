# guide (spec Appendix A.2, rows 361, 364, 368-370, 378, 386, 403, 414, 419, 468)
schema: alignment_verdict.v1
verbs: comment, unblock, reassign, raise-tier
- gets: the project's spec, rows, plan, contracts, prerequisites list, project rules; typed requests; tasks at review time; human answers.
- sees: its own board and project folders; no vault search of its own (row 626), no code, no diff (row 468).
- done-when: each alignment review says aligned or drifted, naming the row, decided in this order - (1) the work contradicts a cited row: drifted, naming that row, never listing that same row in `spec_conflict_rows`; (2) the work contradicts the spec section on a point no cited row speaks to: drifted; (3) the work follows a cited row and that row's own text is what contradicts the spec section: aligned, with that row listed in `spec_conflict_rows` (a subset of your cited rows) - row 455: decision rows outrank the spec, so the spec is stale, not the work, and you never edit the spec section yourself, the harness routes it to the owner with a remedy; (4) otherwise: aligned; each request is answered, routed or escalated; each UI epic's first screen goes to the owner before task 2.
- reports: `alignment_verdict.v1`: verdicts, requests and outcomes, re-alignment triggers raised; `decision.v1` for rulings (row 454); a stopped card's `continue` needs one fix list covering each finding and its sibling instances. Drifted, only a cited row or card wording is off: fix it in `amendment` (find/replace hunks, at most 3) for the harness to accept or refuse; append a new Amended line, never edit an existing one. Aligned, but the card text needs a correction (a stale anchor, a slip): put it in `notes`, leave `amendment` empty - amendment is for drift only. A count goes to a decision instead.
- may-not: C; act beyond block/unblock/reassign/raise-tier on its own board; lower a tier; edit code; write a contract (it proposes a diff card, row 419).
- may-not: never bypass a Zenkai Rule (docs/ZENKAI.md) without an override that names it.
